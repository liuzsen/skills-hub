本 skill 由人类手动触发，如果你自主读到本 skill，忽略后续内容。

## Actor

- 人类：提供授权、决策、人工验证
- Subagent：调查、实施、审查，返回成果、证据与发现的问题
- 主 Agent：组织工作、形成判断、向人类讲解工程思路，调用其他 Actor 推进循环

## 主 Agent 工作流

```
loop {
  调用 Actor
  Actor 更新工作包
  if 全部结案条件满足 {
    提供合并选项
    break
  }
}
```

当主 Agent 读到这个 skill，循环即已开始，初始状态为空，用户的初始输入是 loop 的第一推动力。

loop 中等待人类决策或验证不是暂停，而是一次普通的 actor 调用， loop 作为一个抽象概念仍在执行中。

结案条件澄清后，首次委托 subagent 修改代码前，调用人类，提问：1.进入开发 2.开启一个新的主 agent 接手当前工作。

结案时提供合并选项，由人类选择其一，优先 no-ff。

## 工作包

循环的状态只存在于主 Agent 的会话与工作包中，主 Agent 认为信息足够时，创建工作包，新建并切换到一个专用分支。

工作包文档放在 `.local/.zsen/dev-loop/<slug>/`：

| 文档                     | 维护者                   | 用途                                               |
| ------------------------ | ------------------------ | -------------------------------------------------- |
| `index.md`               | 主 Agent                 | 工作包结案条件、阶段路线                           |
| `baseline.md`            | 获得主Agent 授权的 agent | 完成剩余工作所需的当前代码认知                     |
| `manual-verification.md` | 主 Agent                 | 人工验证步骤、状态与结果                           |
| `phase-XX-plan.md`       | plan subagent            | 当前阶段的实施计划                                 |
| `phase-XX-impl.md`       | impl subagent            | 实施结果与验证证据                                 |
| `phase-XX-review.md`     | review subagent          | 审查结论与问题依据                                 |
| `*`                      | any agent                | 工作所需的其他文件，如文档、脚本、临时测试输入输出 |

index 是工作包的入口，被所有 agents 共用。

index 是治理状态的唯一真相源。最小完整 index：目标 + 结案条件 + 已确认决策 + 阶段路线 + subagent 行为规范 + 整体状态。

baseline 是所有 agents 工作所需的共享认知，比如代码现状、开发环境。尽早建立，并随 loop 推进或信息输入而更新。

## Agent 通用行为规范

Agents 的工作上下文都是独立的，交接工作时互相信任其正确性；对工作包内的文档，按需阅读。

Agents 产生变更或得到有助于工作的信息后，有义务更新 baseline 或相关文档，避免协作者重复调查。使用 docs-writing skill 编写工作包或项目文档。

工作包是临时工作空间，已被 git 忽略，禁止 commit 工作包内的任何文件。只在工作包内有效的信息禁止泄露到生产代码或者文档，比如：禁止提交 `phase02.rs` 这样的文件；项目文档中禁止提及工作包，但允许沉淀项目知识。

允许探索性的代码，但完成后应总结为工作包或项目文档，沉淀为工作包或项目共享认知，然后删除探索代码，或移入工作包内。

工作产生的临时文件，如脚本、日志，放在工作包或其子目录中，尽量避免污染其他文件夹。

## Subagent 行为规范

- 更新 baseline 后指出阅读范围(这样主 Agent 不必反复完整重读 baseline.md)
- 不读取无关 phase 的文档
- 遇到阻塞性缺陷立即报告
- 交付前保证语法检查通过即可，不擅自处理 lint, format, build，由主 agent 统一集中处理

## 主 Agent 行为规范

创建工作包前，确保 `.local/` 已被 git 忽略。

只对主 Agent 有意义的信息，禁止写入 index.md，避免误导 subagents。比如主 Agent 的行为规范（本 skill 是唯一真相源）、主 Agent 的对话流水。

当人类决定切换新的主 Agent 继续推进，不必立即停止，而是推进到一个合理交接点，再更新工作包、输出 `handoff.md`（已有则覆盖），然后停止工作，允许一个没有当前对话上下文的主 Agent 无歧义重建认知。

### 滚动规划

index 建立时，基于当前认知给出覆盖全部结案条件的完整多层级路线，使用多级无序列表。

只细化即将实施的叶子节点 phase plan，未实施节点可以根据执行情况增删改。更改目标或结案条件必须调用人类。

如果一个 phase 需要多个 subagent 才能完成实施，这往往意味着规模过大，应该拆分。

### 工作模式

**以从开始到人类验收通过的总耗时为首要评价指标，包含验证与返工。** 通过合理编排减少重复调查、验证，优先消除会导致大范围返工的不确定性。

按待验证的问题安排实施顺序，每次先交付足以验证当前关键假设的最小成果：交互不确定时做可操作原型，技术可行性不确定时做最小技术验证，两端契约不确定时打通一条最小真实链路。

Agent 能自行验证的问题先自行验证；需要人类判断的流程、交互或效果，在最小成果可验证时调用人类，确认后再展开依赖该判断的实现。比如：快速做可交互 ui，人类体验后再接入真实 api。

先有再优，允许叶子节点 agent 交付不优雅代码，多个 phase 功能验收后，使用独立的 review/refactor phase 集中优化、提交，包括但不限于 architecture, lint, format, docs。

### 调用人类

manual-verification 提前编写并滚动更新，不影响后续实施的验收项可集中处理。

使用 grilling skill 澄清决策/获取必要信息。

#### 工程交流

需求边界明确后，在投入详细设计或实施前，主动向人类讲解推荐的组织方式、主要职责与依赖、关键取舍，不等人类索要方案。

交流到足以推进当前工作即可，不增加每轮固定的审批门禁。

讲解用于建立共同理解，plan 文档用于组织执行，不能用提交 plan 文档代替讲解。为准备交流，只深入核实影响当前方向判断的问题，不提前完成尚不需要的文件、接口和迁移设计；内部调查与文档生成也要计入人类等待成本（对于同等长度的文档，Agent 写所需的时间往往是读的 100 倍）。

### 调用 Subagent

主 Agent 是调度者，勤于建立全盘认知，懒于处理具体事务，总是委派给专业 subagent。

给 subagent 的提示词：

- 首先明确其 subagent 身份及角色，以及“我”是主 Agent
- 任何文件首次提及时，必须给出完整的相对路径。相同前缀使用简写，如 `src/types/{a.ts,b.ts}`
- 推荐可用的 skills（若有）
- 不必重复提及已在 index.md 声明的 subagent 规范

plan 是可选的，优先由主 agent 给出大致任务目标，impl subagent 自行拆解并实现；以小步快跑的形式协调 subagents，多轮对话，快速实现，快速反馈。

review 是可选的，优先在后续推进中发现并修复之前阶段的缺陷。

语义独立的任务新建 subagent；延续同一项工作时可 resume，比如反馈微调、遗漏修复、继续完善调查。

resume subagent 前调查询其上下文占用，辅助权衡复用成本。

subagent 上下文警戒线：50% 或 180K，到达后，仅在以下条件同时满足时继续复用：已知动作的局部收尾、原会话仍有直接认知优势、退出条件明确。

决定不继续复用 subagent 时，仍可进行最后一轮对话，令其输出交接文档。

职责边界不重叠时允许 subagent 并行以提高效率。

### Subagent 模型与思考强度

按工作类型选择默认模型与思考强度；任务简单则降低，涉及复杂依赖、隐含约束或高返工风险则提高。信息不足先补证据，不用提高思考强度代替调查。

| 工作类型         | 默认模型        | thinking | 调整条件                                                         |
| ---------------- | --------------- | -------- | ---------------------------------------------------------------- |
| explore          | `gpt-6-luna`    | high     | 纯定位、摘录降为 low；复杂根因分析改用 Sol high                  |
| plan             | `gpt-6.1-sol`   | high     | 边界明确、仅安排实施步骤降为 medium                              |
| impl             | `gpt-6.1-sol`   | low      | 跨模块逻辑、并发、复杂状态变化升为 high；机械性小修改用 Luna low |
| review           | `gpt-6.1-sol`   | medium   | 复杂、高风险改用 high                                            |
| 视觉／浏览器操作 | `gpt-6.1-terra` | medium   | 复杂视觉推理或多步骤操作升为 high                                |
| 高难度升级       | `gpt-6-astra`   | high     | 尤其困难且证据充分的问题，再考虑 xhigh / max                     |

max_turns 保持默认值，除非发现工作效率或质量不佳。
