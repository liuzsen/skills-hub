# 宪法写入规则

宪法只保存项目约定，不复制本 skill 的治理规则；草案留在对话中。

## 条款与理由

同一条款只定义一次，归属于能完整解释它的最小上下文；其他位置只链接，不追加条件。

可独立变更或归属不同上下文的条款分开表达，不强拆共同演化的语义。

条款须脱离理由也能正确理解。仅当缺少理由会让未来 agent 合理重提已拒绝方案时，记录决定性的约束与权衡；理由只解释，不另设规则。

废止即删除，历史交给 Git。仍需禁止的方案写成现行排除项；失去依附的理由一并清理，有效部分移至相关条款。

涉及协议、Schema、状态模型等规则引用时，读取 [规则采纳](authority.md)。

## 术语

术语定义所属项目或 Domain 决策范围内的统一语言。同一上下文用词一致，跨域异义须明确区分。

在所属上下文中按以下格式定义影响决策的术语，在确有混淆风险时保留 `Avoid` 行：

```
**{术语}**：{术语在决策范围内的精确定义}
_Avoid_：{其他易混淆的术语列表}
```

## 内容与表达

条款直接表达约定，写清会影响判定的适用范围与例外；必要理由后置，不写推导过程。

按内容组织，不套固定章节。

必要事实背景为约定表达服务，不独立罗列项目现状，不补写显而易见的内容。

## 布局

`docs/zsen/constitution/` 下：

- `index.md`：项目的边界、全局约定。
- `domains/<slug>.md`：局部边界、约定。
- `rationales/<slug>.md`：由相关条款引用的理由。
- `models/<slug>.<ext>`：被采纳的规则模型。

Domain 是可独立推理的稳定决策上下文，不等同于模块或部署单元。仅当拆分能减少任务所需上下文时才拆，不因存在通信就新建协调域。

文件与章节按需创建，所有条款须从入口可达。

## 写后检查

检查受影响部分的定义唯一性、导航与失效内容；

检查是否可调整架构，如章节重排/合并/拆分、拆分 domain，有则提议。
