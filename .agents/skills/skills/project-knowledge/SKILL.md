# 项目知识：宪法与记忆

Git 存历史，代码和测试存事实，宪法只存两者残差：无法从项目事实中低成本、无歧义地重建的现行长期约定。

记忆是项目事实的导航与摘要，不是规范依据。

权威性：`宪法 > 实现 > 记忆`。当三者出现偏差，修改低权威性 artifacts。

## 读取

读取 `docs/zsen/constitution/index.md` 和 `docs/zsen/memory/index.md`，再按当前任务需要跟随链接。

## 维护记忆

记忆保存跨任务有用、重复调查有成本的已核实事实，例如架构地图、命令的使用条件、代表性实现入口。不是工作记录。

完成任务所需的调查后，自问：哪些信息沉淀后可以显著降低本次调查的成本？

完成项目变更后，自问：哪些修改值得跨任务共享？

识别到有用记忆后，按 [记忆写入规则](references/project-memory.md) 直接更新记忆，并在任务结束时简要告知。

## 维护宪法

行为可重建，不代表承诺可重建，代码可以表达做了什么，但无法表达应该做什么、不做什么。

留意对话和代码中的约定与排除项：若持续影响未来决策，且无法从项目事实可靠重建，核对现有条款，提议更新宪法。

任何宪法修改均须用户事前明确授权。使用 grilling 提问时，用户同意即授权，不必反复确认。获授权后按 [宪法写入规则](references/constitution-model.md) 执行。

初始化宪法时，只建立最小种子。
